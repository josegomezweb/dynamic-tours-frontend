---

## 1. Punto de partida

Dynamic Tours cuenta actualmente con una plataforma operativa en funcionamiento, tanto en la parte pública como en la zona privada para agencias.

El sistema ya dispone de lógica interna, contenidos, fichas de viaje, listados, reservas, presupuestos, facturación y acceso de agencias (entre 800 y 1.000 accesos diarios de agencias minoristas).

El objetivo de esta primera fase **no es modificar esa lógica ni intervenir en el backend**, sino realizar una actualización visual y desarrollar una nueva capa frontend preparada para que el equipo técnico de Dynamic pueda conectarla posteriormente al sistema existente.

---

## 2. Objetivo de la Fase 1

La Fase 1 se centra en renovar la imagen digital de Dynamic Tours y preparar el frontend principal de la plataforma.

El trabajo incluye:
1. Actualización visual de la marca aplicada a web.
2. Rediseño de las pantallas principales.
3. Maquetación frontend (HTML / CSS / React / Tailwind).
4. Mejora de la experiencia visual y responsive.
5. Preparación de una base frontend ordenada para su posterior conexión técnica.

Esta fase sigue un enfoque similar al planteado inicialmente en KIP Viajes: **primero definir y desarrollar la capa visual/frontend, y posteriormente conectar esa capa con los datos reales y la lógica interna**.

---

## 3. Alcance Incluido

### 3.1. Branding aplicado a interfaz
* Revisión estética general.
* Paleta visual aplicada a la web (azules corporativos, contraste B2B).
* Tipografías y jerarquías de texto.
* Estilo de botones, enlaces y llamados a la acción.
* Tratamiento visual de imágenes.
* Cabeceras, menús y pies de página.
* Criterios responsive para móvil, tablet y escritorio.
* Coherencia visual entre parte pública y zona agencia.

### 3.2. Rediseño frontend de la web pública
* Home pública.
* Navegación principal.
* Menús y cabeceras.
* Listados de viajes y ofertas.
* Cards de viaje.
* Bloques de precio.
* Presentación de destinos.
* Fichas informativas de viaje.
* Secciones de "qué incluye" y "qué no incluye".
* Itinerarios día a día.
* Observaciones e información complementaria.
* Bloques de descarga o consulta de PDF cuando formen parte de la ficha.
* Adaptación responsive de las principales vistas públicas.

### 3.3. Rediseño frontend de pantallas principales de agencia (intranet)
* Home de agencia / intranet.
* Navegación principal de agencia.
* Accesos a reservas, facturas, mensajes y datos.
* Listados visibles dentro del área agencia.
* Tablas básicas de consulta.
* Presentación visual de reservas o facturas cuando sean pantallas de consulta.
* Coherencia visual entre la experiencia pública y la experiencia privada.

### 3.4. Maquetación frontend
* Maquetación HTML/CSS con Tailwind y componentes reutilizables.
* Ajustes responsive.
* Aplicación de estilos a botones, tablas, cards, menús y bloques de contenido.
* Adaptación visual de las pantallas principales.
* Preparación del frontend para su posterior integración por parte del equipo técnico de Dynamic.
* Pruebas básicas de visualización en escritorio y móvil.

---

## 4. No Incluido en esta Fase (Límites claros)

Esta Fase 1 **NO** incluye:
* Conexión con backend o motor interno.
* Conexión con base de datos.
* Integración con datos reales en producción.
* Modificación del motor de reservas.
* Lógica de disponibilidad de vuelos o cupos.
* Cálculo de precios o presupuestos dinámicos.
* Categorías, extras, seguros o excursiones en backend.
* Pasarelas de pago.
* Permisos y roles internos.
* CRM.
* Facturación avanzada.
* Generación automática de documentos/PDFs desde servidor.
* Formularios con validaciones complejas de backend.
* Cambios de base de datos o arquitectura PHP.

> **Nota técnica:** La conexión técnica del frontend con la lógica existente quedará en manos del equipo técnico de Dynamic (Víctor/Elena) o podrá plantearse como una Fase 2 posterior independiente.

---
